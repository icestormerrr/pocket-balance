# Тестовая модель

## Unit

- Расположение: рядом с кодом, в `__unit__/`.
- Имена: `*.test.ts` или `*.test.tsx`.
- Инструмент: Jest.
- Проверяют наблюдаемое поведение одного модуля.
- Внешние зависимости мокируются. Мок создаётся заново для каждого теста.
- Проверяются результат, ошибки и аргументы вызовов зависимостей.
- Не запускают браузер и не используют реальное хранилище.

Команда: `npm run test:unit`.

### Что покрываем unit-тестами

- Сервисы: каждый публичный метод, валидация, ошибки и вызовы репозиториев/сервисов.
- Репозитории: преобразование данных, фильтры и операции с хранилищем.
- Общие утилиты: расчёты, преобразования и граничные значения.
- Общие хуки: возвращаемое состояние и публичные действия.
- Компоненты: пользовательское поведение, состояния и callback-контракты.

Приватную функцию не тестируем отдельно, если она вызывается только из уже покрытого публичного метода. Отдельный тест нужен, если это переиспользуемая чистая функция или в ней есть самостоятельное сложное правило.

## Integration

- Расположение: рядом с проверяемой страницей или виджетом, в `__integration__/`.
- Имена: `*.spec.ts` или `*.spec.tsx`.
- Инструмент: Playwright.
- Проверяют связку UI, роутинга, сервисов и хранилища.
- Данные теста изолированы; тест не зависит от результатов другого теста.

### Что покрываем integration-тестами

- Страницы: UI → сервис → хранилище
- Виджеты: UI → сервис → хранилище

Команда: `npm run test:integration`.

## Visual

- Расположение: `__integration__/visual/`.
- Инструменты: Storybook и Playwright.
- Проверяют только визуально значимые состояния: данные, пустой экран, ошибка, create/edit, выбранный фильтр.
- Базовое состояние: мобильный viewport и тёмная тема.
- Снимки обновляются только при осознанном изменении интерфейса.
- Baseline генерируются и сравниваются на одной платформе CI.

### Что покрываем visual-тестами

- Страницы и виджеты
- Общие компоненты

Команды: `npm run test:visual`, `npm run test:visual:update`.

## E2E

- Расположение: `e2e/`.
- Инструмент: Playwright.
- Проверяют критические пользовательские потоки: первый запуск, операции со счетами, транзакции, переводы, отчёты.
- Не дублируют unit- и integration-сценарии.

### Что покрываем E2E-тестами

- Сквозные пользовательские сценарии между несколькими страницами.

Команда: `npm run test:e2e`.
